## Ideia central

<DefinitionBlock title="Diagnóstico de rede é separar camadas" text="Primeiro confira IP e rota. Depois teste alcance, DNS, porta e resposta da aplicação. Cada comando responde uma pergunta diferente." />

## IP e rota

```bash
ip addr
ip route
hostname -I
```

`ip addr` mostra interfaces e endereços. `ip route` mostra por onde o tráfego sai.

## Conectividade

```bash
ping -c 4 8.8.8.8
ping -c 4 example.com
traceroute example.com
```

`ping` pode ser bloqueado por firewall, então falha de ping não prova sozinha que o serviço está fora.

## DNS

```bash
dig example.com
nslookup example.com
getent hosts example.com
```

DNS transforma nome em endereço. Se IP funciona e nome não funciona, suspeite de resolução.

## HTTP e download

```bash
curl -I https://example.com
curl -L https://example.com
curl -v https://example.com
wget https://example.com/arquivo.zip
```

`curl -I` mostra cabeçalhos. `curl -v` ajuda a enxergar conexão, TLS e resposta.

## Portas abertas

```bash
ss -tulpen
ss -ltnp
```

`ss` substitui bem o antigo `netstat` em muitos sistemas.

<ExampleBlock title="Serviço web não responde" text="Confira ss -ltnp para ver se a porta está ouvindo. Depois use curl -I localhost:porta. Se local funciona e remoto não, investigue firewall ou rota." />

<TipBlock title="Pergunta antes do comando" text="Cada comando deve responder algo: tenho IP? resolvo DNS? alcanço o host? a porta está ouvindo? a aplicação responde?" />
