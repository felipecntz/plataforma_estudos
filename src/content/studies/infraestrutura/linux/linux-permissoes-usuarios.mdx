## Ideia central

<DefinitionBlock title="Permissão é controle de ação" text="No Linux, cada arquivo informa quem pode ler, alterar ou executar. Isso protege configurações, serviços e dados de usuários." />

## Lendo permissões

```bash
ls -l script.sh
```

Exemplo:

```text
-rwxr-xr-- 1 ana dev 1200 jul 19 10:00 script.sh
```

Leitura rápida:

| Parte | Significado |
| --- | --- |
| `r` | read, pode ler |
| `w` | write, pode escrever |
| `x` | execute, pode executar |
| primeiro trio | permissões do dono |
| segundo trio | permissões do grupo |
| terceiro trio | permissões dos outros |

## chmod

```bash
chmod +x script.sh
chmod 644 arquivo.txt
chmod 755 script.sh
```

Valores comuns:

| Modo | Uso comum |
| --- | --- |
| `644` | arquivo comum: dono escreve, outros leem |
| `600` | arquivo privado |
| `755` | diretório ou script executável |
| `700` | diretório privado executável pelo dono |

## chown e grupos

```bash
sudo chown usuario:grupo arquivo.txt
sudo chown -R app:app /opt/app
groups
id
```

`chown -R` altera recursivamente. Use com atenção.

## sudo

```bash
sudo apt update
sudo systemctl status nginx
sudo journalctl -u nginx
```

`sudo` roda o comando com privilégio elevado. Em servidor, isso é poder real.

<WarningBlock title="Evite chmod 777" text="chmod 777 dá leitura, escrita e execução para todo mundo. Pode parecer resolver rápido, mas costuma criar risco de segurança." />

<ExampleBlock title="Tornar script executável" text="chmod +x backup.sh permite executar o arquivo com ./backup.sh, desde que o conteúdo seja um script válido." />
