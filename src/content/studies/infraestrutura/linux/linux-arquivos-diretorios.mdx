## Ideia central

<DefinitionBlock title="Operações de arquivo mudam o sistema" text="Criar, copiar, mover e remover arquivos são tarefas simples, mas em infraestrutura elas podem afetar serviços. Use caminhos claros e confira o alvo." />

## Criar arquivos e pastas

```bash
mkdir logs
mkdir -p backups/2026/julho
touch app.log
```

`mkdir -p` cria diretórios intermediários se eles ainda não existirem.

## Copiar

```bash
cp app.conf app.conf.bak
cp -r site site-backup
cp -i nginx.conf /tmp/nginx.conf
```

`-r` copia diretórios. `-i` pergunta antes de sobrescrever.

## Mover e renomear

```bash
mv antigo.txt novo.txt
mv app.log logs/
mv -i config.yml config.yml.old
```

O mesmo comando `mv` serve para renomear e mover.

## Remover

```bash
rm arquivo.tmp
rm -i arquivo.tmp
rmdir pasta-vazia
rm -ri pasta-com-arquivos
```

<WarningBlock title="rm não manda para lixeira" text="Em servidores, rm geralmente remove de verdade. Evite comandos amplos, caminhos soltos e remoção recursiva sem conferir o alvo." />

## Exemplos de operação

```bash
mkdir -p /tmp/revisao-linux
cp /etc/hosts /tmp/revisao-linux/hosts.bak
ls -lh /tmp/revisao-linux
rm -i /tmp/revisao-linux/hosts.bak
```

<ExampleBlock title="Backup antes de editar" text="Antes de alterar um arquivo de configuração, copie para nome.bak. Se a edição der errado, você tem uma referência imediata." />

<TipBlock title="Use -i quando estiver aprendendo" text="cp -i, mv -i e rm -i tornam comandos destrutivos mais conversacionais. É um freio simples enquanto você ganha segurança." />
