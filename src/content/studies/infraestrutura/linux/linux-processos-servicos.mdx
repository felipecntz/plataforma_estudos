## Ideia central

<DefinitionBlock title="Serviço é processo gerenciado" text="Um processo é um programa rodando. Um serviço é um processo administrado pelo sistema, normalmente iniciado no boot e controlado por comandos padronizados." />

## Ver processos

```bash
ps aux
ps aux | grep nginx
top
htop
pgrep nginx
```

`top` mostra consumo em tempo real. `htop` é mais amigável, quando instalado.

## Encerrar processos

```bash
kill 1234
kill -9 1234
pkill nginx
```

`kill` envia sinal. `kill -9` força encerramento e deve ser último recurso.

## Controlar serviços com systemctl

```bash
systemctl status nginx
sudo systemctl start nginx
sudo systemctl stop nginx
sudo systemctl restart nginx
sudo systemctl enable nginx
sudo systemctl disable nginx
```

`enable` configura início automático no boot. `start` inicia agora.

## Ver logs com journalctl

```bash
journalctl -u nginx
journalctl -u nginx -f
journalctl -u nginx --since "1 hour ago"
```

<ExampleBlock title="Investigar serviço parado" text="Rode systemctl status nginx para ver estado geral. Depois use journalctl -u nginx --since '1 hour ago' para procurar erro recente." />

<WarningBlock title="Reiniciar não é diagnóstico" text="Reiniciar pode aliviar o sintoma, mas confira logs e causa provável. Em produção, reinício sem contexto pode esconder falhas recorrentes." />
