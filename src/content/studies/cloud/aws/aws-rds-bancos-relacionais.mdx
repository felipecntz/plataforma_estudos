## Ideia central

<DefinitionBlock title="RDS é banco relacional com operação gerenciada" text="Amazon Relational Database Service permite criar bancos como PostgreSQL, MySQL, MariaDB, Oracle e SQL Server sem administrar manualmente instalação, patches básicos, backups e parte da disponibilidade." />

RDS não elimina o trabalho de banco de dados. Você ainda precisa modelar tabelas, criar índices, controlar queries, definir permissões, monitorar custo e planejar crescimento. O ganho é reduzir a operação de infraestrutura do banco.

## O que você escolhe ao criar

| Decisão | Impacto |
| --- | --- |
| Engine | recursos SQL, compatibilidade e operação |
| Classe da instância | CPU, memória e custo |
| Storage | tamanho, desempenho e crescimento |
| Multi-AZ | maior disponibilidade |
| Backup | recuperação em caso de erro |
| Subnet group | onde o banco ficará na rede |
| Security group | quem pode conectar |

<TipBlock title="Macete" text="RDS é gerenciado, mas não é mágico. Query ruim, índice ausente e conexão aberta demais continuam sendo problema seu." />

## Multi-AZ e réplicas

Multi-AZ cria uma instância reserva em outra zona de disponibilidade para failover. O foco é disponibilidade. Read replica cria uma cópia para leitura, útil para aliviar consultas pesadas. O foco é escala de leitura.

```text
Multi-AZ -> resiliência
Read replica -> escala de leitura
Snapshot -> cópia em um momento específico
Backup automático -> recuperação por janela de tempo
```

## Segurança

O banco normalmente deve ficar em subnet privada. A aplicação acessa o RDS por security group. Administradores podem acessar por VPN, bastion host, Session Manager ou outra rota controlada.

<WarningBlock title="Erro comum" text="Colocar RDS público por conveniência. Banco de produção exposto à internet aumenta muito a superfície de ataque." />

## Resumo de revisão

RDS é a escolha natural quando a aplicação precisa de banco relacional e você quer reduzir operação. Escolha engine, tamanho, storage, backup e rede com cuidado. Multi-AZ melhora disponibilidade; read replica ajuda leitura. Segurança começa com subnet privada, security group restrito e segredo fora do código.
