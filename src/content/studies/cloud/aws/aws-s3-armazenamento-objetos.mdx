## Ideia central

<DefinitionBlock title="S3 guarda objetos, não discos" text="Simple Storage Service é armazenamento de objetos. Ele não funciona como uma pasta local montada em um servidor comum; cada item é um objeto acessado por chave dentro de um bucket." />

S3 é um dos serviços mais usados da AWS porque serve para muitos cenários: imagens, documentos, backups, logs, exportações, data lakes e sites estáticos. Ele é durável, integrado com vários serviços e precisa de atenção forte a permissões.

## Bucket, objeto e chave

| Conceito | Resumo |
| --- | --- |
| Bucket | contêiner onde objetos são armazenados |
| Objeto | arquivo mais metadados |
| Key | nome/caminho lógico do objeto |
| Prefixo | início da key usado para organizar |
| Metadata | informações associadas ao objeto |

<TipBlock title="Macete" text="S3 parece pasta, mas não é sistema de arquivos tradicional. `pastas` são prefixos nas chaves dos objetos." />

## Segurança de acesso

O padrão mental deve ser bloquear acesso público e liberar somente o necessário. Use IAM para permissões de identidades, bucket policy para regras do bucket e URLs pré-assinadas quando alguém precisa acessar um objeto por tempo limitado.

```text
Boas perguntas:
Quem precisa ler?
Quem precisa escrever?
Por quanto tempo?
De qual origem?
O dado precisa ser público mesmo?
```

<WarningBlock title="Erro comum" text="Deixar bucket público para resolver download rápido. Para arquivos privados, use autenticação na aplicação ou URL pré-assinada com expiração." />

## Versionamento e lifecycle

Versionamento guarda versões antigas de objetos, ajudando contra exclusão acidental e sobrescrita indevida. Lifecycle move ou remove objetos conforme regras, reduzindo custo quando dados ficam antigos.

<ExampleBlock title="Exemplo realista" text="Logs diários podem ficar 30 dias em classe padrão, depois migrar para uma classe mais barata e finalmente expirar depois de um ano." />

## Resumo de revisão

S3 armazena objetos em buckets. A key organiza o caminho lógico. Segurança depende de IAM, bucket policy e bloqueio público. Versionamento protege contra alterações acidentais. Lifecycle controla custo. Use S3 para arquivos e objetos, não como disco local de EC2.
