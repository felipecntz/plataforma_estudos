## O que e DCL

DCL significa Data Control Language. Ela controla permissoes.

Comandos principais:

- `GRANT`: concede acesso;
- `REVOKE`: remove acesso.

No PostgreSQL, o conceito central e `ROLE`. Uma role pode funcionar como usuario, grupo ou ambos.

## Criando roles

Role de leitura:

```sql
CREATE ROLE analista_readonly
LOGIN
PASSWORD 'senha_forte_aqui';
```

Role de aplicacao:

```sql
CREATE ROLE app_user
LOGIN
PASSWORD 'senha_forte_aqui';
```

Grupo sem login:

```sql
CREATE ROLE equipe_dados;
GRANT equipe_dados TO analista_readonly;
```

## Permissao no schema

Antes de ler tabelas em um schema, a role precisa conseguir usar o schema.

```sql
GRANT USAGE ON SCHEMA public TO analista_readonly;
```

## Permissao em tabelas

Somente leitura:

```sql
GRANT SELECT ON ALL TABLES IN SCHEMA public TO analista_readonly;
```

Leitura e escrita para aplicacao:

```sql
GRANT SELECT, INSERT, UPDATE, DELETE
ON ALL TABLES IN SCHEMA public
TO app_user;
```

Permissao em uma tabela:

```sql
GRANT SELECT ON clientes TO analista_readonly;
GRANT SELECT, INSERT ON pedidos TO app_user;
```

## Sequences e identity

Quando tabelas usam sequences, a role pode precisar de permissao nelas.

```sql
GRANT USAGE, SELECT
ON ALL SEQUENCES IN SCHEMA public
TO app_user;
```

## Permissoes futuras

Para novas tabelas criadas depois:

```sql
ALTER DEFAULT PRIVILEGES IN SCHEMA public
GRANT SELECT ON TABLES TO analista_readonly;

ALTER DEFAULT PRIVILEGES IN SCHEMA public
GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO app_user;
```

## REVOKE

Remover permissao:

```sql
REVOKE DELETE ON pedidos FROM app_user;
```

Remover tudo:

```sql
REVOKE ALL PRIVILEGES ON clientes FROM analista_readonly;
```

## Boas praticas

- nao use superuser na aplicacao;
- separe usuarios de leitura e escrita;
- evite compartilhar senha entre pessoas;
- use roles de grupo para padronizar acesso;
- registre quem tem acesso a dados sensiveis;
- revise permissoes periodicamente.

<WarningBlock title="Permissao demais vira risco silencioso" text="Um usuario de relatorio nao precisa de DELETE. Uma aplicacao comum nao precisa ser dona do banco nem superuser." />

<TipBlock title="Modelo simples" text="Crie uma role readonly para consultas, uma role app para a aplicação e mantenha administracao separada. Isso ja evita muitos acidentes." />
