## Criando a estrutura

```bash
python -m venv .venv
source .venv/bin/activate
pip install django psycopg[binary]
django-admin startproject config .
python manage.py startapp core
python manage.py startapp produtos
```

Estrutura comum:

```text
meu_projeto/
├── manage.py
├── config/
│   ├── settings.py
│   ├── urls.py
│   ├── asgi.py
│   └── wsgi.py
├── core/
├── produtos/
├── templates/
│   └── base.html
└── static/
```

## Projeto vs app

O projeto e a casca global. A app e um modulo.

Exemplos de apps:

- `core`: home, paginas gerais, utilitarios visuais;
- `produtos`: catalogo, estoque, categorias;
- `pedidos`: pedido, status, itens;
- `financeiro`: cobrancas e pagamentos.

<TipBlock title="Nao crie apps demais cedo" text="Uma app por dominio claro costuma bastar. Separar demais no inicio aumenta caminhos, imports e decisoes pequenas." />

## settings.py

Campos que voce mais olha:

| Configuracao | Uso |
| --- | --- |
| `INSTALLED_APPS` | apps nativas, terceiros e apps locais |
| `MIDDLEWARE` | camadas de request/response |
| `ROOT_URLCONF` | arquivo de URLs principal |
| `TEMPLATES` | busca de templates |
| `DATABASES` | conexao com banco |
| `STATIC_URL` | caminho de arquivos estaticos |
| `LANGUAGE_CODE` | idioma |
| `TIME_ZONE` | fuso |
| `DEBUG` | modo desenvolvimento |
| `ALLOWED_HOSTS` | hosts aceitos |

## Registrando uma app

```python
INSTALLED_APPS = [
    "django.contrib.admin",
    "django.contrib.auth",
    "django.contrib.contenttypes",
    "django.contrib.sessions",
    "django.contrib.messages",
    "django.contrib.staticfiles",
    "produtos",
]
```
